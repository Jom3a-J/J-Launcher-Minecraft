# Security Policy

## Supported versions

Once a stable release exists, security fixes will target the newest stable
Windows x64 version. During release-candidate qualification, reports should
identify the exact Git commit or artifact hash used.

## Reporting a vulnerability

Do not open a public issue for a vulnerability that could expose accounts,
tokens, user data, signing credentials, release integrity, or destructive
filesystem behavior.

Use GitHub's private vulnerability-reporting form:

<https://github.com/Jom3a-J/J-Launcher-Minecraft/security/advisories/new>

Include the affected version or commit, Windows version, reproduction steps,
expected impact, and relevant logs with credentials and personal paths removed.
Do not upload proof-of-concept material to a public paste or file host.

The project is maintained by one person and cannot promise a response time,
but reports will be investigated in good faith. Publication is paused whenever
artifact provenance or integrity may be affected; future signing is also paused
if any signing account or process is implicated.
